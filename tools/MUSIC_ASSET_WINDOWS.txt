Sonic Colors Recomp — music_asset on Windows
============================================

The Music Library uses `tools/music_asset.exe` (or `music_asset.cmd`) to:
  - build/update catalog.json
  - decode original AAX previews (vgmstream)
  - export original WAV
  - prepare patched CPK replacements (cricodecs)

Required (same roles as Linux):
  1. Python 3.11+ on PATH (`python` / `py -3`)
  2. cricodecs (via tools\music_deps_setup.cmd → .venv-music)
  3. vgmstream-cli — PATH or drop into tools\bin\
  4. ffmpeg — PATH or drop into tools\bin\ (prefer an LGPL build)

Quick setup:
  1. tools\music_deps_setup.cmd          → .venv-music + cricodecs
  2. Copy ffmpeg.exe + vgmstream-cli.exe into tools\bin\
  3. tools\music_asset.exe doctor        → JSON ready/blocked ops
  4. Music tab → Check tools             → same report in the UI

Works immediately (no host tools):
  - Browse catalog
  - Preview assigned replacement WAVs
  - Play with an already-prepared music_mods cache

Needs setup:
  - Original preview / export → Python + cricodecs + vgmstream
  - Prepare replacements → Python + cricodecs + ffmpeg

The redistributable ZIP ships:
  - `mods/music/catalog.json` (full Music Library inventory; required to browse tracks)
  - `tools/music_asset.exe`, `tools/music_asset.cmd`, and `tools/music_asset_pkg/`
  - `tools/music_deps_setup.cmd`, `tools/bin/README.md`
  - `tools/libwinpthread-1.dll` (beside music_asset.exe)

It does not bundle Python, cricodecs, vgmstream, or ffmpeg (licence / size).
Doctor distinguishes missing vs unusable binaries (bad drop-ins). Re-run Check tools
after changing tools\bin.

`manifest.toml` and `tracks/` are created next to the catalog when you assign
replacements in the Music tab (not shipped).

Replacement CPK cache (`music_mods/current.json`) is created by Prepare. A
“not prepared yet” status is normal until then — original previews/export still
use the game CPK directly (they need vgmstream on PATH).

Override the launcher path with SCR_MUSIC_ASSET.
